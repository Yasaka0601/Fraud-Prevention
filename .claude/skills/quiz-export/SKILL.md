# 本番クイズの書き出しと Notion の更新

本番DB（Neon）のクイズ・選択肢・カテゴリ・コース・画像URLを
`tmp/exports/quizzes.json` と `tmp/exports/quizzes.md` に書き出し、
Notion クイズDB と `tmp/quiz_drafts/*.md` を本番の内容に合わせる。

## 大事な前提
- **書き出しは毎回ではなく、ユーザーが必要と思ったときに行う**。クイズ作成（`/quiz-draft`）の重複チェックは Notion を使うので、書き出しは不要
- **本番が正**。ユーザーは RailsAdmin に登録するときに、改行・ポイントなど細かい箇所を手で直している。そのため本番と Notion・案のファイルには必ずズレが出る。ズレは本番に合わせる
- Render 無料プランでは rake タスクを実行できないため、**ユーザーのPCの Docker から Neon に接続**して実行する
- **書き出しのコマンドはユーザーが自分のターミナルで実行する。Claude は実行しない**
  - 接続文字列（パスワード入り）を Claude が受け取らないため
  - ユーザーのターミナルで読み込んだ `NEON_URL` は、Claude の Bash からは使えないため
- 接続には読み取り専用ユーザー `quiz_reader` を使う（本番データは変更できない）
- `tmp/` は Git 管理外。書き出したファイルはコミットされないが、消えることもある

## 1. 事前確認（Claude）
1. `docker compose ps` で web コンテナが起動しているか確認する。止まっていれば Docker Desktop の起動と `docker compose up` を依頼する
2. `ls -la tmp/exports` で前回のファイルの有無と日時、`quizzes.json` の `count` を伝える
3. ユーザーに「`quiz_reader` のパスワードを覚えているか」を聞く

## 2. 書き出し（ユーザー）
同じフォルダの `neon-guide.md` を読み、ユーザーの状況に合う部分を案内する。
- パスワードを覚えていない → 「A. パスワードを作り直す」から
- 覚えている → 「B. 接続文字列を用意する」から
- 初めて／`quiz_reader` がない → 「0. 初回だけ」から

案内するときは、手順を省略せず、ガイドの文面をそのまま見せる。
ユーザーには「成功したら件数だけ教えてください」と伝える。

## 3. 結果の確認（Claude）
`tmp/exports/quizzes.json` を読んで報告する。
- 合計件数（前回から何件増えたか）
- カテゴリ別の件数
- `image_url` が入っている件数
- 件数が前回より減っていたら、ユーザーに伝える
- **登録ミスの疑い**があれば伝える（本番の修正はユーザーが RailsAdmin で行う）
  - 正解の選択肢が1つもないクイズ
  - 問題文に「複数回答可能」と書かれているクイズ（書かないルールなので修正漏れ）

## 4. Notion の「採用」を「登録済み」にする（Claude）
Notion「詐欺対策道場 クイズDB」（data source: `collection://38822343-3766-456d-b982-42f06a843c38`）で、ステータスが「採用」のページを探す。

1. 各ページのタイトルと、`quizzes.json` のクイズ名（`name`）を照合する
2. 照合結果を表にして見せる（Notionのタイトル / 見つかった元ID / 画像の有無）
   - 見つからないもの、同じ名前が複数あるものは「要確認」として表示し、更新の対象から外す
3. 「この内容で Notion を更新してよいか」を聞く。**許可が出るまで Notion を変更しない**
4. 許可が出たら、各ページを次のように更新する
   - 元ID：照合したクイズの `id`
   - ステータス：「登録済み」
   - 本番で画像が付いていれば、画像あり にチェックし、画像ファイル名 を入れる。画像は `image_url` からダウンロードし、Notion にアップロードして「### 問題文」の後に貼る
5. 更新したページのURLを報告する

「採用」のページがなければ、このステップは飛ばして 5. へ進む。

## 5. Notion と案のファイルを本番に合わせる（Claude）
元IDが入っている Notion のページ（4. で更新したものも含む）を、`quizzes.json` の同じ `id` のクイズと比べる。

### 比べる項目
| 項目 | Notion | 本番（`quizzes.json`） |
|---|---|---|
| タイトル | タイトル | `name` |
| ポイント | ポイント | `give_point` |
| カテゴリ | カテゴリ | `categories` |
| コース | コース | `courses` |
| 選択肢数 | 選択肢数 | `choices` の数 |
| 問題文 | 本文「### 問題文」 | `sentence` |
| 選択肢・正解 | 本文「### 選択肢」 | `choices`（`text` と `is_correct`） |
| 解説 | 本文「### 解説」 | `explanation` |

- 改行の違いも差分として扱う（本番の `\r\n` は改行1つとして比べる）
- 本番のコースが空（`courses` が `[]`）のときは、Notion のコース「コース未実装」と同じとみなす
- 本番にあって Notion にないクイズは「Notion に未登録」として一覧にする（追加するかはユーザーに聞く）

### 手順
1. 差分のあるクイズを一覧にして見せる。クイズごとに「項目 / Notion / 本番」の表にする。本文の差分は、違う行だけを抜き出して見せる
2. 同じクイズの案が `tmp/quiz_drafts/*.md` にあれば（タイトルで照合する）、そのファイルも直す対象として一緒に見せる
3. 「本番に合わせて更新してよいか」を聞く。**許可が出るまで Notion もファイルも変更しない**。一部だけ許可された場合は、そのクイズだけ更新する
4. 許可が出たら、本番の内容で上書きする
   - **Notion**：プロパティと本文（「### 問題文」「### 選択肢」「### 解説」）を本番の内容にする。正解の選択肢は ✅ と**太字**、不正解は ⬜
     - 本文の先頭の「新コース案：〇〇」「コース：なし（余った問題）」は、本番でコースが空のときは残す（Notion のコースは「コース未実装」のまま）。本番でコースが付いていたら消す
     - 本番のコースが Notion のコースの選択肢にないときは、更新する前にユーザーに伝える
   - **`tmp/quiz_drafts/*.md`**：該当する案の「コース」「ポイント」「問題文」「選択肢」「解説」を本番の内容にする。「ひっかけポイント」「似ている既存クイズ」はそのまま残す
5. 更新した Notion ページのURLと、直したファイルのパスを報告する

## やらないこと
- 書き出しコマンドの実行（ユーザーが行う）
- 接続文字列・パスワードを受け取る、表示する
- 本番DB・RailsAdmin の変更（登録ミスの疑いは伝えるだけ）
- 元IDのないページ（下書きなど）の変更
- ユーザーの許可なしでの Notion・ファイルの変更
- Git操作（ブランチ・コミット・push・PR）
