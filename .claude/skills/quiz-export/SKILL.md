# 本番クイズの書き出しと Notion の更新

本番DB（Neon）のクイズ・選択肢・カテゴリ・コース・画像URLを
`tmp/exports/quizzes.json` と `tmp/exports/quizzes.md` に書き出し、
Notion クイズDB の「採用」ページを「登録済み」にする。

## 大事な前提
- Render 無料プランでは rake タスクを実行できないため、**ユーザーのPCの Docker から Neon に接続**して実行する
- **書き出しのコマンドはユーザーが自分のターミナルで実行する。Claude は実行しない**
  - 接続文字列（パスワード入り）を Claude が受け取らないため
  - ユーザーのターミナルで読み込んだ `NEON_URL` は、Claude の Bash からは使えないため
- 接続には読み取り専用ユーザー `quiz_reader` を使う（本番データは変更できない）
- `tmp/` は Git 管理外。書き出したファイルはコミットされないが、消えることもある

## 1. 事前確認（Claude）
1. `docker compose ps` で web コンテナが起動しているか確認する。止まっていれば Docker Desktop の起動と `docker compose up` を依頼する
2. `ls -la tmp/exports` で前回のファイルの有無と日時、`quizzes.json` の `count` を伝える
3. ユーザーに「`quiz_reader` のパスワードを覚えているか」を聞く

## 2. 書き出し（ユーザー）
同じフォルダの `neon-guide.md` を読み、ユーザーの状況に合う部分を案内する。
- パスワードを覚えていない → 「A. パスワードを作り直す」から
- 覚えている → 「B. 接続文字列を用意する」から
- 初めて／`quiz_reader` がない → 「0. 初回だけ」から

案内するときは、手順を省略せず、ガイドの文面をそのまま見せる。
ユーザーには「成功したら件数だけ教えてください」と伝える。

## 3. 結果の確認（Claude）
`tmp/exports/quizzes.json` を読んで報告する。
- 合計件数（前回から何件増えたか）
- カテゴリ別の件数
- `image_url` が入っている件数
- 件数が前回より減っていたら、ユーザーに伝える

## 4. Notion の更新（Claude）
Notion「詐欺対策道場 クイズDB」（data source: `collection://38822343-3766-456d-b982-42f06a843c38`）で、ステータスが「採用」のページを探す。

1. 各ページのタイトルと、`quizzes.json` のクイズ名（`name`）を照合する
2. 照合結果を表にして見せる（Notionのタイトル / 見つかった元ID / 画像の有無）
   - 見つからないもの、同じ名前が複数あるものは「要確認」として表示し、更新の対象から外す
3. 「この内容で Notion を更新してよいか」を聞く。**許可が出るまで Notion を変更しない**
4. 許可が出たら、各ページを次のように更新する
   - 元ID：照合したクイズの `id`
   - ステータス：「登録済み」
   - 本番で画像が付いていれば、画像あり にチェックし、画像ファイル名 を入れる。画像は `image_url` からダウンロードし、Notion にアップロードして「### 問題文」の後に貼る
5. 更新したページのURLを報告する

## やらないこと
- 書き出しコマンドの実行（ユーザーが行う）
- 接続文字列・パスワードを受け取る、表示する
- 本番DB・RailsAdmin の変更
- 「採用」以外のページの変更
- Git操作（ブランチ・コミット・push・PR）
